Each errand can make one guarantee-backed booking; open a fresh errand for another reservation. Without recorded bounds the host uses the usual principal purchase card. Use credential_authority with a job's exact thread before it submits a signup or password-change form the principal asked for; send the returned authority to the job. The host generates and saves the password; never put a password in a message or file. change_password covers only a login the assistant created or saved itself and nobody has since edited; not_owned means it is the principal's to change. Each authority covers one submission; after outcome_unknown, never record another to retry. When the job cannot settle an attempt, release with its thread and authority asks the principal to end it.
