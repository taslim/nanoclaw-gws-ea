## Public web reads

first passes the production capability hook, then a fixture egress check that
rejects email addresses (including encoded URLs), invented private identities,
phones and private markers. The actual native SDK exercised those refusals
against a scripted loopback API before any public read. No successful search
result is invented. Exact requests/results stay in web-reads.jsonl; raw SDK usage
retains server-tool usage and reported costs. A paired baseline must preserve
public source conditions or disclose changes. Successful public reads and their
behavioral inference have not been run in this checkpoint; the user's current
direction permits local tests only.

The abandoned context.route interception reached an automatic POST before the
native document policy; it is not used. Its failed local evidence is retained.

The bounded alternative, preserved only as local prototype evidence, used the actual owned Chrome
runtime, unchanged public-only proxy, native BrowserQueue and action handler.
It intercepts only the response stage after a real public example.com GET; it
never replaces a tool result. Before the local-only decision, it observed native
purchase-control refusal, principal-email refusal before typing and ungranted
liability-waiver consent refusal before submission. A normal HTTPS443 automatic
POST had an independent exact-URL Network.setBlockedURLs fuse. A fused GET alone
did not set native guard.reason; the automatic POST did set blocked_address.
Its later CDP notification carried BlockedByClient with no HTTP response status,
and the native refusal was already recorded at that notification. The fuse
prevented any external POST even if the native guard had failed.

The overall proof remains false. A private loopback HTTPS address produced a
native handler-error rather than an attributable blocked_address outcome, so
that subproof is incomplete. Actual main-to-browser multi-actor model execution
also remains absent. No browser fixture transport is integrated or advertised
as available. New public-network probes are outside the current local-only
verification authorization; the unadopted prototype source and its exact gap remain in local evidence,
outside active scenario code.
